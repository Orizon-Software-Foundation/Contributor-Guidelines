# Developer and Contributor Guidelines

Welcome! Thank you for choosing to contribute to our foundation. These are the guidelines both external and internal contributors should follow to ensure a smooth working environment.

---

# 1 - Artificial Intelligence Usage Policy
The use of Artificial Intelligence (AI) within aspects of projects such as code, pull requests, and issues is _**strictly forbidden**_. Use of AI will result in a blacklist from this foundation, no exceptions.

---

# 2 - Code of Conduct
Any and all participation within our foundation is mainly governed by our Code of Conduct. In short: Be friendly and respectful, mind those around you, assume good faith, stay on topic, and be patient with newcomers. If you believe a user/contributor/maintainer is in violation of one or more of these rules, please do not hesitate to report it at our email address (contact@orizonsoftwarefoundation.org). **Note: Matters that involve rule breaking should not be reported publicly.**

---

# 3 - Ways to Contribute
You can contribute to any one of our projects by doing one or more of the following:

- Report bugs: Clear and concise bug reports help you and the maintainers in the long run.
- Suggest features: Make an issue and suggest new features be implemented.
- Write code: Help us finish a project/a portion of a project earlier than usual.
- Improve documentation: Read the code and improve documentation for future users down the road.
- Test and review: Help us spot bugs or flaws on different platforms.
- Translate: Translate documentation or comments into other languages for others to read.
- Help others: Assist others in the forums with issues and questions.

All of these are very helpful ways to contribute to our foundation and would be greatly appreciated.

---

# 4 - Pull requests
A maintainer will view your pull request usually between 2 hours - 7 days of you creating it. If no real progress is made after this time frame, a ping is acceptable and is standard practice. 
Please remember that:
- Changes should go in pull requests, not issues.
- Review is always about the code, never about the person. Feedback is meant to help you and the project grow.
- Respond to review comments by pushing new commits or explaining your reasoning from another standpoint. Do not take change requests personally.
- At least one maintainer approval is required to merge your code into the project
- Maintainers may close pull requests that are inactive for more than 2 weeks.

---

# 5 - Reporting issues
Before opening an issue, think about whether your issue meets the requirements demonstrated below.
Your issue must have: a short and descriptive title, steps to reproduce such problem, expected behavior vs actual behavior, version, operating system, and relevant details, logs, screenshots, and/or error output where helpful. 
**Security vulnerabilities should be reported immediately to (contact@orizonsoftwarefoundation.org) with a patch and instructions for implementation. It should only be released to the public after 7 days of no response and the patch should be publicized. .**

---

# 6 - Licensing and Legal
By contributing to any project within this foundation, you agree to follow the license that is stated in the `LICENSE` file within the root directory of the project itself.
**We require contributors to sign off on their commits, as this adds a** `Signed-off-by: Your Name <you@example.com>`, **certifying that you wrote the contribution or otherwise have the right to submit it under the project's license.**

We also credit contributors in the release notes and within the `CONTRIBUTORS` file if applicable.


Thank you dearly for contributing to our foundation and helping us with our goals.
